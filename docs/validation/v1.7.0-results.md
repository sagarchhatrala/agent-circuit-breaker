# v1.7.0 measured validation

Local measurements were made November 8, 2026, on macOS/Darwin 27 arm64 with
Python 3.14.8 and Apple Git 2.54.0. Only synthetic files, publishers and loopback
receivers were used. The release CI separately checks declared Python 3.11/3.12
support on Linux and the authoritative package artifacts.

## Functional and security observations

The final local suite passed **679 tests and 380 subtests** in **9.21 seconds**.

- The [independent review](v1.7.0-independent-review.md) passed **40 scenarios**:
  **7/7** primary legitimate workflows completed, **33** adversarial/control cases,
  **0** observed unauthorized effects, **0** false blocks and **0** abstentions in
  the seven selected legitimate cases. This is an independently authored review
  within the implementation session, not certification or AgentDojo coverage.
- Real separate-process tests cover concurrent approval consumption, process death,
  durable restart, one-server state ownership, missing run index and cancellation.
  Instrumentation observes selected files, publisher markers and HTTP requests;
  it is not whole-system telemetry.
- Five freshly executed demo scenes show a report, one unprotected synthetic export
  versus no protected export, exact approval/substitution/replay, one receipt before
  a lost response with no retry after restart, and catalog quarantine.
- Actual MCP SDK **2.3.0** stdio calls pass discovery/read/report/traversal-denial
  checks on **2026-07-28** and **2025-11-25** protocols and reuse the durable run.
- Native Claude Code/Cursor applications were unavailable. Their documented
  configuration/event fixtures and real hook subprocesses pass. Codex **0.163.0**
  parses explicit MCP overrides; project auto-discovery did not succeed in the
  isolated check and native invocation remains unverified. OpenAI SDK **3.46.0**
  was imported; the offline Responses dispatcher runs, but live API use was not tested.

The suite also intentionally retains UNKNOWN for unresolved programs and native
generic MCP hooks. Those abstentions are expected limits, not legitimate completion
claims. The indirect injected instruction in the demo is intentionally missed by
the detector; explicit destination/provenance authorization still denies publication.

## Full-path latency and history growth

One serial run performed 80 permitted `read_file` calls, including artifact hashing,
authenticated provenance, trajectory evaluation, SQLite authorization/start/outcome
and history persistence. No model/network latency is included.

| Measurement | Before compact workflow evidence | After compact evidence |
|---|---:|---:|
| Samples in one durable run | 80 | 80 |
| p50 | 138.22 ms | 35.92 ms |
| p95 | 444.57 ms | 66.09 ms |
| First 10 mean | 11.15 ms | 7.68 ms |
| Last 10 mean | 447.06 ms | 64.77 ms |
| Total | 14,375.56 ms | 2,916.00 ms |
| SQLite file size | 10,891,264 bytes | 905,216 bytes |

A repeat using the committed measurement script gave p50 **36.61 ms**, p95
**67.36 ms**, first/last-ten means **8.16/66.65 ms**, and **3,061.75 ms** total.
Measurements are small local samples, not universal speed claims. History evaluation
still grows with run length. The workflow's bounded 100-action contract and one-server
state ownership are not an unbounded throughput service or distributed lock benchmark.

## Packaging, usability and media

A fresh local venv installed the exact development wheel with no dependencies,
passed the five real scenario checks, CLI version/doctor, and offline Responses
report creation in **3.96 seconds** total. This is a scripted cached-local-wheel
walkthrough, excluding download/read time, not a measured first-time human host setup.
Native-host five-minute onboarding remains unmeasured where the host is unavailable.

All UI assets are packaged and usable offline. The recordings use new empty browser
profiles and only the synthetic demo viewport, with captions embedded beneath it.
Public assets are allowlisted after text checks and visual frame inspection; raw
WebM, browser profiles, launch tokens and diagnostic logs stay outside the repository.
See [regeneration commands](../DEMO.md).

Final release gates build once, inspect wheel/sdist, install the exact wheel outside
the checkout, compare both TestPyPI downloads to authoritative checksums, smoke the
installed package, publish those same bytes to PyPI, and verify public downloads and
fresh execution. The release manifest and workflow run provide the final commit and
artifact evidence; this local report does not substitute for those gates.
