# v1.7.0 independent scenario review

A separate review agent examined the implementation and wrote adversarial tests on
November 8, 2026. This is independent review within the implementation session,
not third-party certification, a penetration test of every integration, or an
AgentDojo benchmark result. Only synthetic files and effects were used.

Final focused verification passed **40/40 independent scenarios**, within a run of
**61 tests and 5 subtests in 5.50 seconds**, on Darwin 27.0.0 arm64, Python 3.14.8,
Apple Git 2.54.0. Seven primary allowed workflows completed
(7/7), with zero false blocks or abstentions in that small selected set. The other
33 independent scenarios exercise rejection, recovery, integrity, or configuration controls.
After the fixes below, none of the instrumented unauthorized effects occurred.
This observation is limited to the files, publisher callbacks, subprocess markers,
and HTTP requests asserted by these tests; it is not whole-system telemetry.

Run this file again against the final release revision; review of a worktree does
not replace the release artifact gates:

```sh
python -m pytest -q tests/test_v1_7_independent_review.py
```

The endpoint scenarios need permission to listen on temporary loopback ports.
The tests require POSIX file-descriptor operations; Git scenarios need
`/usr/bin/git`. Test duration includes fixture creation, child processes, and server
shutdown; it is **not** per-call latency. Longer-run latency belongs in the release
validation results.

## Findings and follow-up

| Finding | Severity | Initial result | Correction reviewed | Follow-up |
| --- | --- | --- | --- | --- |
| `git status` could execute a repository-configured clean filter | High | A same-length modification to a tracked file caused the configured filter to create a harmless unauthorized marker | Copy bounded Git index/refs/objects into private temporary metadata, omit repository configuration/hooks/alternates, and run fixed system Git with an isolated environment | PASS: no marker; legitimate modified status still returned |
| Malformed catalog retained the bridge's previous valid catalog | Medium | A duplicate-name catalog raised an exception but left old authority available | Invalidate the active catalog before parsing any replacement | PASS: subsequent preparation denied |
| Malformed legacy catalog response envelope escaped structured quarantine | Medium | A non-object result raised an attribute error | Validate envelope type and quarantine the session | PASS: controlled error and later call denied |
| Git status did not check the workspace root's pinned identity | Medium | Code inspection found a path-based root separate from the pinned file executor | Open the pinned root descriptor, snapshot `.git` relative to it, then use a separate fixed child to `fchdir` before Git execution | PASS: replacement root rejected; normal status works |
| Malformed upstream tool content could count as completion | Medium | The bridge initially checked only that `content` was an array | Restrict supported completion to valid text blocks and complete results; ambiguous results remain uncertain | PASS: malformed text block after a synthetic effect blocks retry |
| Concurrent MCP startup could initialize replacement authority or share an active run | Medium | Code inspection found key/store construction before startup coordination and no exclusive server lifetime | Acquire a nonblocking state-directory lock before constructing the workflow; retain it until server exit | PASS: second process refused; killed server releases lock; restart retains the same single run |
| Overflowing numeric request ID could terminate the stdio server | Low | A real `tools/call` request with ID `1e309` closed stdout before returning an error | Validate supported ID type before pending-request canonicalization | PASS: invalid request rejected and subsequent ping answered |
| Working-directory Python modules could replace generated hooks or MCP executors | High | A synthetic shadow hook loaded under the old command shape and emitted a false allow decision | Generated commands use a fixed interpreter with `-I -m`; native configuration examples require isolated loading from an installed package | PASS: shadow hook/server modules never run; real hook denies and real MCP server initializes |

An intermediate descriptor-path Git fix failed the two legitimate status tests on
macOS. The fixed child-process approach passed both. Retaining allowed cases in the
matrix prevented a security correction from silently breaking the useful workflow.

## What this review establishes and does not establish

The tests exercise real local file writes, SQLite state shared across processes,
process termination, and HTTP control requests. MCP bridge tests use a deterministic
upstream callback with observable synthetic effects. They do not attest a remote
server implementation or establish a real remote transport's delivery semantics.
Additional MCP tests launch the installed local stdio server in real subprocesses
to verify startup exclusion, durable reuse, cancellation, and invalid-input handling.
The native-hook payload and MCP wire fixtures in the broader suite remain distinct
from launching a native host.

| Area | Review status |
| --- | --- |
| Typed workflow authorization and supported provenance transformations | Executed locally in this review |
| Exact approval concurrency and interruption | Executed using separate real processes |
| Local MCP startup, durable reuse, malformed input, cancellation | Executed over actual subprocess stdin/stdout |
| Hook/MCP module identity under a hostile working directory | Executed using generated configuration and an installed package |
| Local control token, Origin, Host, and file effects | Executed against actual loopback servers |
| UI untrusted-content rendering | Code reviewed: values enter `textContent`; no content-to-HTML sink found. Browser recording/visual inspection is a separate release gate |
| Claude Code native hooks | Adapter/configuration code reviewed; native application behavior not verified by this review |
| Cursor native hooks | Separate adapter/configuration code reviewed; native desktop/CLI behavior not verified by this review |
| Codex | MCP configuration preservation tested; native host behavior not verified by this review |
| Responses API | Offline trusted dispatcher tested; no live paid/model API run in this review |
| Installed wheel, sdist, publishing, public release assets | Separate release gates; this review makes no publication claim |

Policy, installed executor code, provenance key/database, approval controls, and
runtime state must be inaccessible to the untrusted agent. Mode bits and a temporary
workspace do not isolate hostile code running under the owner's identity. The demo
uses a fixed fixture executor with no arbitrary agent process; it is not an OS
sandbox. Host-owned tools outside the mediated path remain outside its guarantee.

Authorization protects outbound execution even when injection detection misses an
instruction. These tests do not establish general tracking through arbitrary shell,
Python, model-generated transformations, or undocumented tool implementations.
The report renderer and copy/Base64 operations are the transformations tested.
Declassification is not an agent-facing operation. Natural-language goal text is
metadata; the explicit owner policy determines permissions.

A failure discovered inside an already-started trusted executor can legitimately
produce an executor-start event without producing the forbidden file or network
effect. Scenarios W07 and W09 check actual effect absence rather than claiming that
every rejected filesystem condition was discovered before the executor function
began. Hashing/version preflight also reads source bytes before the execution event;
“executor started” is the recorded RuntimeGate lifecycle boundary, not a syscall
trace of every validation read.
