# v1.7.2 execution verification

Release preparation, November 9, 2026. All workflows use temporary synthetic data,
loopback servers and disposable containers. No production database, real cloud
credential or external recipient is involved.

## Observed locally

- macOS, Python 3.14.8 / SQLite 3.54.1: **722 pytest tests and 444 subtests passed**.
- `unittest discover`: **722 tests passed**. The legacy shell/SQL/MCP/audit/hook
  rehearsal passed **133/133 checks** on version 1.7.2.
- Fresh isolated Python 3.11 and 3.12 wheel installs outside the checkout executed
  the package smoke and actual owner CLI/SQLite workflow. The Python 3.12 wheel
  also passed both real MCP SDK protocol flows.
- Actual owner CLI: initialized a project; read/copied and independently checked
  bytes; previewed, approved and committed exactly one SQLite row; rejected replay;
  exported and verified all events in signed pages.
- Actual MCP SDK 2.3.0: both `2026-07-28` and `2025-11-25` stdio routes completed
  real file operations. The owner route also completed approved SQLite maintenance
  and refused replay/unapproved execution. Host configuration lifecycle was tested
  for Claude, Cursor and Codex; native host applications were not certified.
- Owner workflow rehearsal, seeds 172 and 173: **33/33 observed-effect checks each**
  against Moto, including real HTTP uploads retrieved independently via boto3.
  Final version 1.7.2 seed 172 request latency p50 6.469 ms / p95 22.994 ms;
  development seed 173 p50 6.153 ms / p95 25.046 ms (56 requests each). These measurements are
  environment-specific, include approved operations and are not detector benchmarks.
- Fault rehearsal forwarded a real S3 PUT, withheld its response and killed the
  owner. The object existed afterward; restart retained the byte reservation and
  refused replay. No claim of distributed exactly-once delivery follows from this.

The real workflows also verified label-preserving transformations, owner-only
declassification, denied sensitive export, cumulative row/byte limits, concurrent
approval consumption, stale database snapshots, expired approval, authority-field
injection, traversal refusal and exported-evidence tampering.

## Reproduction

```bash
python -m pytest -q
python -m unittest discover
python scripts/verify_appsec_demo.py --output /tmp/appsec.json
python -I scripts/owner_smoke.py
python -I scripts/mcp_sdk_smoke.py
python -I scripts/verify_owner_workflows.py --seed 172 --output /tmp/owner.json
python scripts/verify_owner_isolation.py --wheel dist/agent_circuit_breaker-1.7.2-py3-none-any.whl
```

MCP SDK requires `mcp==2.3.0`; the owner rehearsal requires `boto3` and
`moto[server]`, or `--s3-endpoint http://127.0.0.1:9000 --verify-signature` for a
disposable MinIO server. Linux Docker is required for the isolation script.
CI uploads the container/S3 reports as `owner-execution-evidence`.

The corpus is finite, synthetic acceptance coverage. It does not measure all
prompt injections, arbitrary SQL semantics, universal information flow, host-agent
containment, live AWS behavior, comparative product effectiveness or immutable
audit. The exact boundaries are in [the owner guide](../OWNER_SERVICE.md).
