# v1.7.1 verification — 9 November 2026

The source candidate passes **696 tests and 440 subtests**, plus the separate
unittest discovery run. The safe local rehearsal passes **133 checks** on macOS
with Python 3.14.8. The built wheel also passes all 133 checks outside the checkout
on Python 3.11.18 and 3.12.16. MCP SDK 2.3.0 interoperates over both tested protocol
modes, and the installed wheel passes the five package smoke scenarios. Wheel and
sdist metadata checks pass. The release workflow repeats tests/rehearsal on Linux with
Python 3.11 and 3.12 and exercises the authoritative wheel before publication.

The previous v1.7.0 investigation is retained in
[the historical report](appsec-2026-local-verification.md). It found real scope
escapes, HTTP forwarding failures, CLI-option misses and a broken pre-commit
entry even though the old unit suite passed. v1.7.1 includes those fixes and
closes the subsequently identified SQL, uninspectable MCP and authentication gaps.

## Direct execution evidence

- Harmless shell commands create real temporary files through RuntimeToolExecutor;
  traversal, dash-prefixed and redirect-hidden out-of-scope writes never reach it.
- Disposable SQLite tables survive denied DROP, unqualified/tautological changes,
  stacked statements and CTE deletes. An explicitly allowed `id=1 AND 1=1` delete
  now executes and removes exactly one row.
- A real synthetic secret read and real database export precede attempted uploads
  to a loopback collector. Denied uploads do not reach it; a public control does.
- Real stdio/HTTP MCP processes record which requests arrive upstream. Empty and
  numeric-only calls stop. An explicitly granted empty tool succeeds; the grant
  cannot authorize a numeric argument object.
- Signed ledgers verify and replay; changed entries with recomputed public hashes
  fail HMAC verification and replay. An independently retained checkpoint detects
  truncation. Four real concurrent processes append 48 entries to each log without
  breaking either chain.
- Real pre-command hooks, pre-commit, SARIF generation, and SQLite runtime restart/
  authorization replay exercise the same installed code paths.

Of the 133 rehearsal checks, one explicitly demonstrates that **unconfigured
legacy ledger mode is unsigned**. That is an authentication migration control,
not a security guarantee. Configure a protected `ACB_AUDIT_HMAC_KEY`, use
`verify(require_signature=True)` when authentication is mandatory, and retain
checkpoints outside the agent's reach.

## Reproduction

```bash
python -m pip install -e . pytest pre-commit
python -m pytest -q
python -m unittest discover
python scripts/verify_appsec_demo.py --output /tmp/acb-171-results.json
```

The runner needs POSIX, Git, `touch`, `cat`, and `curl`. Dangerous system/cloud/
publication payloads reach only an inert recorder if a check regresses. SQLite
data and actual uploads are confined to disposable databases and loopback. No
real credential, external upload, or destructive system command is used.

Publication uses the protected main branch and an immutable `v1.7.1` tag. One
authoritative CI build produces the sdist and wheel. TestPyPI and PyPI indexed
bytes must match its SHA-256 manifest; fresh installs and packaged demo checks
must pass. The GitHub release attaches that authoritative provenance.

For exact scope/migration, see [release notes](../releases/v1.7.1.md). Arbitrary
SQL/program semantics, bypassed executors, OS containment, a compromised owner,
and immutable local storage remain outside the guarantee. The legacy HTTP proxy
is a single shared run; native Windows and vendor desktop hosts were not newly
certified by this POSIX rehearsal.
