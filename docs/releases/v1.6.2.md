# v1.6.2 - Inspection Coverage And Decision Validation

Agent Circuit Breaker v1.6.2 strengthens the action decision path by making
mandatory inspection coverage explicit and by validating `ALLOW` decisions before
they leave the runtime.

## Added

- Added `inspection_coverage` to action results. It records whether filesystem,
  command, and SQL inspection completed, which inspectors ran, what limits apply,
  and whether the action is eligible for automatic allow.
- Added `decision_validation` to action results. It records whether a final
  `ALLOW` decision was permitted and why.
- Added MCP argument coverage metadata with inspected field paths and fail-closed
  reporting for invalid or excessively nested tool-call arguments.
- Added approval scoping over policy source, policy trust, policy signature,
  inspection coverage, and decision validation context.
- Added audit event summaries for inspection coverage and decision validation.
- Added regression tests for chained-command auto-allow bypasses, MCP coverage,
  approval scoping, audit summaries, and schema metadata.

## Changed

- Known-safe filesystem auto-allow now requires:
  - a recognized safe filesystem operation,
  - one complete command segment,
  - no shell operators,
  - no command risk flags,
  - valid SQL inspection,
  - no SQL risk flags.
- Chained commands such as a safe filesystem operation followed by an unrelated
  network action no longer inherit the safe first segment.
- Public decision and audit schemas now include the v1.6.2 evidence fields.

## Fixed

- Fixed a bypass where a safe first filesystem segment could cause a later
  chained command segment to be allowed.
- Updated the GitHub scan workflow to use `agent-circuit-breaker`.

## Compatibility

- Existing v1.x JSON fields keep their meaning.
- New result fields are additive.
- Single safe operations such as `mkdir /tmp/example` still return `ALLOW`.
- Multi-segment actions that do not match a block rule remain `UNKNOWN` by
  default, or become `BLOCK`/`PENDING_APPROVAL` under strict or approval policy.
- The default install remains dependency-free.
