# v1.7.1 — AppSec execution-gate fixes

This patch closes defects reproduced against v1.7.0 using real temporary files,
SQLite databases, loopback uploads, MCP proxy processes, and pre-commit hooks.
It also addresses the additional SQL, uninspectable MCP, and ledger gaps found
during that verification.

## Security and correctness

- Write-scope checks canonicalize dot segments while preserving absolute and
  hidden paths. Extensionless/dash-prefixed operands and both command writes and
  redirect destinations are checked. Complex forbidden targets use boundaries.
- HTTP MCP denies notifications without forwarding them, honors trajectory and
  security configuration, and serializes its shared run state. Quarantined calls
  are not counted as forwarded.
- Uninspectable MCP arguments, including empty/numeric-only objects, stop by
  default even with `--allow-unknown`. An owner may explicitly grant a reviewed
  no-argument tool using repeatable `--allow-empty-tool NAME`; that grant applies
  only to an empty argument object and cannot bypass quarantine or prior denial.
- Docker combined short flags, separated Kubernetes grace periods, attached
  curl options, and S3 destination operands now retain their intended risk checks.
- Zero blocked-attempt limits remain zero; boolean numeric limits are rejected.
- SQL checks inspect destructive CTE bodies and the main statement, distinguish
  quoted literals from keywords, and recognize numeric constant comparisons.
  AND/OR precedence prevents `WHERE id=1 AND 1=1` from being mislabeled as a
  tautology. Doubled quotes survive statement splitting.
- Run ledgers support protected-key HMAC signatures and independently retained
  checkpoints. Corrupt ledgers refuse append/replay. Audit and ledger appends
  are serialized across cooperating threads/processes and flushed to disk.
  Checkpoint verification refuses signature stripping when a key is configured.
- The pre-commit hook now invokes the installed `agent-circuit-breaker` command.

## Migration

The stricter MCP behavior is intentional: numeric-only or no-argument calls need
a typed adapter or, for a reviewed empty-argument tool, the explicit grant above.
It is not safe to infer arbitrary tool semantics from a tool name or description.
String-bearing generic tools still require trusted integration and appropriate
policy; the proxy is not a replacement for a tool-specific authorization model.

Set `ACB_AUDIT_HMAC_KEY` in the trusted owner process to authenticate both audit
and run-ledger entries. Use a protected secret of at least 16 bytes. Keep that key,
the state directory, and independently retained checkpoints inaccessible to the
agent. Existing unsigned logs are not retroactively authenticated: archive them
and start a new log when enabling a key. Without a key, legacy unsigned verification
remains available and reports `signature_checked: false`; API callers can require
authentication with `RunLedger.verify(require_signature=True)`.

```bash
agent-circuit-breaker ledger --checkpoint /owner/checkpoints/run.json
agent-circuit-breaker ledger --verify --checkpoint /owner/checkpoints/run.json
```

Checkpoints use the shared audit checkpoint format. A valid prefix can still pass
standalone chain verification after truncation; compare with a separately retained
checkpoint to detect that loss. Local logs are tamper-evident, not immutable.

`allowed_scopes` continues to inspect recognized writes. It does not resolve
symlinks or restrict every read, working-directory change, or arbitrary script.
SQL inspection recognizes finite shapes and abstains on unsupported semantics.
Only ALLOW should execute; the trusted executor and owner isolation remain essential.
The legacy HTTP proxy represents one shared run, not a multi-session gateway.

## Verification

- The independent rehearsal runs real shell/SQLite/loopback/MCP/hook paths and
  verifies executor calls and resulting state, rather than accepting verdicts alone.
- Regression checks also use real concurrent log-writing processes and SQLite to
  prove which predicates modify all rows versus a selected row.
- CI and the tagged Publish workflow run the rehearsal. Publication additionally
  exercises the exact authoritative wheel and real MCP SDK before TestPyPI.
- TestPyPI and PyPI receive the same authoritative distributions; indexed bytes
  are compared with the release manifest and freshly installed before completion.
