# v0.3.0-alpha.1 Release Notes

Release type: alpha prerelease

Tag: `v0.3.0-alpha.1`

Package version: `0.3.0a1`

## Summary

`v0.3.0-alpha.1` adds scoped SQL safety inspection and enforcement to Agent Circuit Breaker. The release detects a narrow set of destructive SQL statements before execution while preserving the existing filesystem and command safety behavior.

## Added

- SQL inspector module with deterministic tokenization.
- SQL statement splitting on semicolons outside quoted strings and comments.
- Destructive SQL detection for:
  - `DROP TABLE`
  - `DROP DATABASE`
  - `TRUNCATE` and `TRUNCATE TABLE`
  - `DELETE FROM <table>` without `WHERE`
  - `UPDATE <table> SET ...` without `WHERE`
- CLI `sql_analysis` output for JSON results.
- Human-readable SQL risk output when SQL danger or parse errors are present.
- Built-in SQL rules that block scoped destructive SQL patterns.
- v0.4 rule loading and validation planning document.

## Changed

- Package version bumped from `0.2.0a1` to `0.3.0a1`.
- Documentation updated from v0.2 command safety alpha to v0.3 SQL safety alpha.
- Roadmap updated to mark v0.3 as released and v0.4 as planned.

## Safety Behavior

These commands now return `BLOCK`:

```bash
circuit-breaker check "DROP TABLE users"
circuit-breaker check "DROP DATABASE prod"
circuit-breaker check "TRUNCATE TABLE users"
circuit-breaker check "DELETE FROM users"
circuit-breaker check "UPDATE users SET active = false"
```

These SQL examples remain unblocked by SQL rules:

```bash
circuit-breaker check "DELETE FROM users WHERE id = 1"
circuit-breaker check "UPDATE users SET active = false WHERE id = 1"
circuit-breaker check "SELECT 'DROP TABLE users'"
circuit-breaker check "SELECT * FROM truncate_log"
```

Unblocked examples may still return `UNKNOWN` when no built-in allow rule classifies them as safe.

## Limitations

- SQL inspection is heuristic and intentionally not a full SQL grammar.
- SQL dialect-specific behavior is not guaranteed.
- Database connection context and production database detection are not included.
- SQL injection detection is out of scope.
- Custom rule file loading is planned for v0.4 and is not included in this release.

```bash
python -m unittest discover

```

- `DELETE FROM users WHERE id = 1`: `UNKNOWN`.
