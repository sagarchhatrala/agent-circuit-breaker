# v1.6.5 - UNKNOWN Execution Hardening

Agent Circuit Breaker v1.6.5 is a targeted security hardening release. It keeps
the v1.x public result contract intact while making executable adapter defaults
more fail-secure.

## Security Improvements

- MCP proxy forwarding now stops `UNKNOWN` tool-call inspections by default.
- Pipeline SDK facade evaluations now treat core evaluator `UNKNOWN` results as
  applicable unknowns by default, so an unrelated guard's `ALLOW` cannot make an
  unclassified action executable.
- `ALLOW` remains the only default executable state for MCP and pipeline SDK
  execution paths.

## Explicit Compatibility Opt-Ins

- Use `agent-circuit-breaker-mcp-proxy --allow-unknown` only when another
  explicit allowlist or review layer is responsible for unclassified tool calls.
- Programmatic MCP integrations can use `MCPRunGuard(allow_unknown=True)` and
  pass `allow_unknown=True` to inspection helpers when they intentionally need
  the previous forwarding behavior.
- Pipeline SDK callers can use `AgentCircuitBreaker(allow_core_unknown=True)`
  when they intentionally want the classic evaluator's `UNKNOWN` to be treated
  as non-applicable inside the SDK facade.

## Compatibility Notes

- Existing v1.x CLI/API result fields and schemas keep their meaning.
- `agent-circuit-breaker check` still reports `UNKNOWN` for unclassified actions
  unless strict, approval, profile, or policy settings transform the decision.
- Existing policy files, rule packs, audit records, approvals, ledgers, and JSON
  schemas remain compatible.
