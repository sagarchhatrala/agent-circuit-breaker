# Agent Circuit Breaker v1.7.0

ACB now connects explicit workflow permissions to real execution through typed
local tools, a durable MCP server, and a packaged demonstration:

```bash
python -m pip install agent-circuit-breaker==1.7.0
agent-circuit-breaker demo
```

The wheel contains all UI assets; the core has no third-party dependencies. Five
scenes show useful report creation, an unauthorized export, exact single-use
approval, interruption/restart, and catalog changes. Proposals are labeled offline;
files, collector receipts and durable decisions are fresh backend observations.

## Changes

- Typed read/status/report/copy/Base64/publication adapters validate arguments,
  principal, resource and exact artifact versions. Authenticated provenance retains
  sensitivity across supported transformations and same-tool export.
- Executor-owned stdio MCP supports 2026-07-28 discovery and legacy initialization,
  durable run reuse, one server per state directory, bounded requests and cancellation.
  A narrow registered remote bridge records uncertain delivery/execution and prevents
  automatic retries. It does not attest a remote server's implementation.
- Runtime start rechecks capability expiry and unresolved execution. Exact approvals
  remain expiring, revocable and single-use. New/removed/changed/malformed catalog
  definitions quarantine until explicit owner review.
- Claude Code and Cursor have separate documented event adapters and project-scoped
  configuration preview, merge, verification and restore. Codex uses documented MCP
  configuration. Generic hooks now deny UNKNOWN and failed checks.
- A Responses function dispatcher wraps actual application execution, handles multiple
  calls and replayed call IDs, and supplies deterministic offline and bounded opt-in
  live modes. No live API or Agents SDK verification is claimed.
- The local UI, captioned overview/walkthrough, poster, independent scenario review
  and reproducible measurements make actual effects inspectable. Compact workflow
  evidence reduces repeated history serialization; existing RuntimeGate event shape
  remains the default.
- Publishing validates a single build, downloads and tests indexed TestPyPI artifacts,
  then promotes the same wheel/sdist bytes to PyPI and verifies a fresh public install.

## Verification and limits

See the [measured results](../validation/v1.7.0-results.md) and
[independent matrix](../validation/v1.7.0-independent-review.md). Final Python 3.11/3.12
and artifact results are recorded by the release workflow; the attached manifest
identifies its exact source revision and SHA-256 checksums.

| Integration | Evidence | Remaining gap |
|---|---|---|
| Claude Code | Documented hook/config fixtures and real adapter subprocesses | Native application unavailable |
| Cursor | Separate desktop-targeted hook/config fixtures | Desktop/CLI unavailable; cloud agents unsupported |
| MCP | Real stdio calls with Python SDK 2.3.0, modern and legacy | New executor is stdio only; legacy HTTP is a custom bridge |
| OpenAI API | Real offline dispatcher; SDK 3.46.0 imported | Live API not run |
| Codex | CLI 0.163.0 parses explicit MCP overrides; TOML merge/restore tested | Project auto-discovery and native invocation unverified |

ACB protects its trusted execution path. Policy, executor code, state/provenance and
approval controls must be inaccessible to the agent. Hooks rely on their host; tools
outside mediation are outside this guarantee. The demo runs fixed fixture operations,
not arbitrary hostile programs, and is not an OS sandbox.

Provenance is limited to supported transformations, not general information-flow
tracking. Unknown scripts abstain; no agent-facing declassification is exposed.
Prose goals and injection findings cannot grant authority. File workflows require
POSIX, and bounded repository status requires `/usr/bin/git` plus a supported layout.

## Compatibility and cleanup

Existing evaluator/runtime/decision/rule APIs remain. The public scaffold function
still supports documented Claude/Cursor paths; unverified Codex/Gemini/Copilot native
generation now fails with migration guidance. New catalog tools require owner review.
See [compatibility](../COMPATIBILITY.md) and [cleanup evidence](../validation/v1.7.0-cleanup.md).

The [demo guide](../DEMO.md) supplies replay, recording regeneration, doctor, reset
and shutdown commands. Release assets contain reviewed synthetic media; raw recordings
and private diagnostics are excluded from the source tree and package.
