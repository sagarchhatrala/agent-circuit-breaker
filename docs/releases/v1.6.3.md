# v1.6.3 - Decision Path Hardening

Agent Circuit Breaker v1.6.3 tightens runtime decision consistency across the
CLI/API, MCP proxy, local run ledger, approvals, and async pipeline SDK.

## Security Improvements

- Blocks dangerous commands hidden behind common shell and interpreter execution
  wrappers, including `sh -c`, `bash -c`, `cmd /c`, PowerShell command wrappers,
  and common interpreter eval flags.
- Adds the built-in `cmd_nested_dangerous_execution` rule for wrapped dangerous
  payloads such as recursive deletes or remote-script-to-shell pipelines.
- Treats applicable `UNKNOWN` guard results in the async pipeline as blockers
  for aggregate `ALLOW`, instead of letting an unrelated allow result hide an
  incomplete guard decision.
- Hardens Windows drive-letter path normalization for safety analysis.
- Detects oversized remote policy responses explicitly instead of reading only
  the configured maximum bytes.

## Evidence And Governance

- MCP custom-rule failure results now include inspection coverage and decision
  validation evidence.
- Local run-ledger replay now preserves action-level engine version, policy
  source/trust/signature, inspection coverage, decision validation, and error
  fields.
- Approval records support optional expiry through `ACB_APPROVAL_TTL_SECONDS` or
  `ApprovalStore(..., ttl_seconds=...)`.

## Compatibility Notes

- This is a compatible security hardening release.
- Some actions that previously returned `UNKNOWN` now return `BLOCK` when a
  dangerous nested payload is detected.
- Existing v1.x result fields keep their meaning. New pipeline validation and
  replay evidence fields are additive.
