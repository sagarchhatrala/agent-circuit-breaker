# v0.5.0-alpha.1 - Rule Schema Alpha

This prerelease hardens the external JSON rule format introduced in v0.4. It makes the schema explicit, exposes deterministic schema metadata, and backs the documented behavior with valid and invalid fixtures.

## Added

- Dedicated external rule schema reference in `docs/RULE_SCHEMA.md`.
- `RULE_SCHEMA_VERSION` constant for the current external rule format.
- `RuleSchema.metadata()` for deterministic schema metadata.
- Valid multi-rule fixture in `docs/examples/rules/multi_rule_guard.json`.
- Invalid fixture examples for duplicate IDs, unsupported matcher types, invalid metadata, and missing `rules`.
- Fixture validation tests covering all documented schema examples.

## Changed

- Rule validation now reports the supported schema version from a shared constant.
- README, quickstart, roadmap, and usage guide now describe v0.5 schema hardening.

## Verification

- `python -m unittest tests.test_rule_loader`
- `python -m unittest discover`
- `git diff --check`
- CLI rule validation smoke tests for valid and invalid fixtures

## Notes

- The rule schema remains JSON-only.
- Regex matchers, YAML, remote rule fetching, rule signing, and dynamic Python matchers remain intentionally unsupported.
