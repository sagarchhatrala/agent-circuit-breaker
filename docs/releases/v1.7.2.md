# v1.7.2 — owner-mediated operations and cumulative effect budgets

Agents can now request useful file, SQLite and S3 operations while a separate
owner process holds resources, credentials and approval authority. The owner
reviews the exact proposed effect before execution; budgets, consumed approvals
and uncertain execution survive restart.

## Added

- `owner init`, `serve` and `verify`: create a synthetic working project, start an
  authenticated Unix service and verify actual file effects and traversal refusal.
- Separate agent/control sockets with OS peer identity checks. Production mode
  requires distinct UIDs; explicit development mode supports local rehearsal.
- Owner-registered parameterized SQLite UPDATE/DELETE, preview on a private copy,
  transactional snapshot revalidation and actual row-count limits.
- S3-compatible SigV4 publication with exact destination/object binding, SHA-256,
  conditional creation, no redirects and no automatic retries after uncertainty.
- Cumulative file/row/export-byte reservations and trusted measured settlements.
  Budget enforcement occurs at atomic execution start, including approved actions.
- Exact fingerprint approval, rejection, inspection, owner-only declassification,
  JSON canonicalization and label-preserving redaction.
- Paginated HMAC-authenticated evidence export and independent verification.
- A thin MCP owner client; guided host configuration via `--owner-socket`.
- A Linux container recipe and reproducible execution checks, including concurrent
  commits, mutation, expiry, replay, restart and forced crash after a real upload.

## Correctness and compatibility

Development verification found and fixed budget deserialization, approved-effect
settlement, SQLite preview transaction handling, occupied-socket replacement,
ambiguous interrupted-request reporting and shadowed SQLite row-identity handling.
Owner CLI exit codes distinguish pending and unknown from successful execution.

The existing evaluator, rule schema, legacy proxy and six-tool Workflow catalog
remain supported. Existing unbudgeted RuntimeGate contracts keep their
fingerprints; effect budgets and the owner route are opt-in. No third-party runtime
dependency was added. Linux/macOS and Python 3.11+ are required for the owner route.

## Verification

See [the measured report](../validation/v1.7.2-results.md). Release gates run the
regression suite, old shell/SQL/MCP rehearsal, real owner CLI and MCP SDK flows,
separate-UID containers and MinIO object/signature checks against the exact wheel.
TestPyPI and public PyPI downloads must match the authoritative checksums and
execute fresh installed workflows before the GitHub release is created.

## Operating limits

ACB is an application authorization gate; OS containment must prevent alternate
resource access. Same-UID development does not provide that containment. SQLite
support is a bounded maintenance profile, not arbitrary SQL/ORM support. Export
budgets count S3 payload bytes, not all possible information flow. Redaction does
not declassify automatically. HMAC evidence is not immutable or resistant to a
compromised owner/key holder. The authority model remains single-host.
