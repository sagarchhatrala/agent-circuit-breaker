The problem

AI agents do not just generate text.

They execute commands, modify files, query databases, call APIs, and touch infrastructure. A bad plan, prompt injection, unsafe tool result, or stale instruction can become a real destructive action.

ACB puts a deterministic control point before execution, so your agent can propose an action without automatically receiving the authority to perform it.

See it work

One unsafe request. One explicit decision.

The goal is not to score a prompt. The goal is to decide whether a specific action is safe enough to execute.

How it works

Three steps before an action executes.

01

Intercept

Send the proposed command, SQL text, MCP tool call, or action context to ACB.

02

Evaluate

Apply deterministic inspectors, built-in rules, custom policy, and trajectory checks.

03

Decide

Return ALLOW, BLOCK, UNKNOWN, ERROR, or PENDING_APPROVAL with evidence.

Why deterministic

Security decisions should not depend on model persuasion.

LLMs are useful for reasoning and planning. Enforcement needs a different property: predictable decisions from explicit policy and inspectable rules.

Current capabilities

Runtime controls that exist today.

Filesystem controls

Blocks recursive deletes, system path deletion, dangerous permissions, and related command shapes.

Destructive SQL detection

Detects DROP, TRUNCATE, unqualified DELETE/UPDATE, and tautological destructive statements.

Policy as code

Supports built-in rules, declarative custom rules, signed policy documents, and strict failure behavior.

MCP proxy mode

Evaluates stdio MCP tool-call arguments and blocks UNKNOWN forwarding by default.

Trajectory checks

Analyzes ordered action sequences for repeated blocks, scope drift, and secret-to-egress patterns.

Audit evidence

Produces explainable decisions with inspection coverage, validation state, approval context, and local ledgers.

Security posture

A control layer, not a magic shield.

ACB evaluates proposed actions before execution. It does not replace sandboxing, operating-system permissions, identity controls, network controls, or human review for high-impact changes.

What it does

Stops known-dangerous actions, marks uncertainty explicitly, and records evidence for audit.

What it does not do

It is not an EDR, SIEM, sandbox, LLM judge, or all-purpose observability platform.
