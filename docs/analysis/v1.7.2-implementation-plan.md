# v1.7.2 implementation and acceptance plan

User-authorized scope: implement the proposed practical execution improvements,
verify real effects in disposable environments, fix discovered defects, and publish
v1.7.2 through protected main and the existing TestPyPI/PyPI release pipeline.

1. Add optional cumulative effect limits to RuntimeGate. Reserve at atomic start;
   settle only trusted measured outcomes; retain uncertain reservations on restart.
2. Add an owner service using the same RuntimeGate for artifact workflows and
   bounded SQLite maintenance. Agent requests cannot grant approvals or authority.
3. Ship an actual S3-compatible publisher with exact object binding, checksums and
   no overwrite; SQLite uses owner-registered parameterized operations, preview on
   a private copy, and transactional revalidation/row limits on actual execution.
4. Provide owner approval/rejection/inspection CLI, reviewed artifact
   declassification, additional deterministic transformations, and independent
   export/verification of authenticated execution evidence.
5. Provide an MCP client for the owner service, guided setup, executable acceptance
   checks, and a Linux deployment recipe with a separate agent identity and no
   protected state/resource mounts or direct external credentials.
6. Publish a reproducible scenario runner measuring actual state, legitimate task
   completion, prevented effects, unexpected denials/unknowns and latency. Include
   competing requests, replay, mutation, service restarts and uncertain outcomes.
7. Run existing tests and live rehearsal, new local end-to-end scenarios, real MCP
   SDK checks, Linux identity/container isolation and real S3 server checks in CI,
   then repeat package verification against authoritative release artifacts.
8. Update current roadmap/support boundaries and release/migration documentation.
   Publish only after all required checks and fresh installs pass.

Compatibility: additions preserve existing evaluation APIs, six-tool Workflow
catalog and legacy proxy defaults. The recommended new owner-service route owns
execution. Existing advisory surfaces remain explicitly labeled. SQLite is the
first supported database dialect; this release does not claim universal ORM/SQL,
arbitrary information flow, multi-host authority, or immutable local storage.

Environment: local host is macOS without Docker/Podman. Local workflow and network
tests use temporary data and loopback services. Linux UID/container enforcement is
verified on disposable GitHub runners before release. No production database,
cloud bucket, real credential or external recipient is used in rehearsals.
