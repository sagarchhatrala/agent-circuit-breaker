# Agent Circuit Breaker v1.7.1: features and market comparison

Reviewed on 9 November 2026 against ACB commit `fb3835fc1b4a15c0193e65b9b7f711428dc4eaef` (tag `v1.7.1`). ACB capabilities below were checked against implementation, the generated rule catalog, CLI, and the release's existing live verification evidence. Competitor capabilities come from the official documentation and repositories linked below; competitors were not installed or benchmarked in this review. This is a selected market comparison, not an exhaustive vendor survey or an independent security certification.

ACB's defensible positioning is a small, local, deterministic authorization runtime for developer-agent actions. Its distinguishing combination is command/SQL inspection, trajectory checks, explicit execution authority, durable handling of interrupted actions, and version-bound artifact provenance in supported adapters. Individual ideas such as pre-execution blocking, deterministic policies, human approval, local deployment, and stateful guardrails are already available elsewhere.

The feature inventory follows. “Implemented” does not mean every feature is enabled by every integration or that every optional integration was exercised in the v1.7.1 live rehearsal.

The strongest ACB differences are concrete combinations:

1. **Operational policy shipped with the runtime.** The package combines normalization and explicit destructive shell/filesystem/SQL checks with the execution integration. A user does not need to begin by designing every validator. Coverage remains finite and should be extended for the application.
2. **Permission binds to the actual proposed effect.** Supported adapters bind canonical action, principal/capability, resource, policy and artifact versions. An approval for one report/destination does not authorize substituted bytes or another destination. The stronger claim depends on the typed or otherwise trusted executor, not arbitrary argument-string inspection.
3. **The lifecycle includes what happened after authorization.** Authorization, start and outcome are separate durable facts. Restart does not erase a consumed approval or turn an unresolved external effect into permission to retry. This is especially useful for publish/export/deletion workflows.
4. **Provenance survives supported transformations.** Copying a sensitive artifact, Base64-encoding it or putting it into the fixed report format preserves its labels; a destination check can stop publication even if an injection detector misses the malicious instruction. This does not generalize to arbitrary model summaries or programs.
5. **Small local deployment and inspectable decisions.** Standard-library core, MIT code, explicit rules, local state and HMAC/checkpoints make it practical to study, embed and demonstrate without an LLM security service. Local deployment and open source alone are shared by several competitors.

ACB currently has weaker coverage for semantic prompt-injection/content classification, enterprise agent discovery/SSO/fleet governance, complete MCP gateway transports, OS containment and general information-flow tracking. Its single-host SQLite authority model does not establish distributed high-availability enforcement. There is no comparative benchmark proving better recall, lower false-positive rates or lower end-to-end latency than the products above.

For a conference introduction, use:

> Agent Circuit Breaker is an open-source, local-first authorization runtime for AI tools. It combines deterministic shell/SQL and trajectory checks with single-use approvals and durable execution records. In its supported typed workflows, permission is bound to the exact resource, policy and artifact version before the executor starts.

For the differentiated demonstration, show: read a classified source; create/copy/encode a report; propose an unauthorized destination; demonstrate that the collector receives nothing; approve an allowed exact artifact; then demonstrate that changed bytes, approval replay and restart after an uncertain effect cannot silently start another execution. This illustrates more of ACB's distinctive implementation than another isolated destructive-command verdict.

Avoid claiming “the first/only tool-call guardrail,” “prevents every prompt injection,” “understands whether an action fulfills the user's goal,” “full MCP firewall,” “universal DLP,” “immutable audit,” “distributed exactly-once execution,” or “works across every agent automatically.” The implementation and market evidence support a narrower, more useful claim.
